# v1.36.0 — Bounded output

Released: 2026-10-02

Three efficiency fixes from a code review. The first one also removes a risk:
one `search` call could fill or overflow the model's context.

## Search and saved-query results have a budget

`search`, `run_saved` and every `saved__<name>` tool run user-written KQL.
Validation warns when such a query has no `take`/`top` bound, or a bound above
`BERSERK_MCP_KQL_MAX_ROWS`, but the query still runs. The whole result then
went to the model. The only limit was `BERSERK_MCP_MAX_RESULT_BYTES` (10 MiB),
which protects the process, not the context window.

These three paths now send at most `BERSERK_MCP_MAX_OUTPUT_CHARS` characters
(default 40,000, about 10k tokens):

- A `bzrk --json` result is cut by whole rows from the start. It stays valid
  JSON with the same columns.
- Table text (a `bzrk` build without `--json`) or an unknown shape is cut at a
  line boundary.
- A result within the budget is not changed.
- A note after the closing `<untrusted_log_data>` tag says how many rows were
  shown, and suggests `take`, a narrower `where`, or `summarize`. The note is
  server text built only from counts, so it stays outside the fence.
- The cut happens before fencing, so the fence is always complete.
- `0` disables the budget.

The analytics tools are not affected. They parse full results to compute
totals, so the budget applies only where raw results go to the model.

`_fence_limited` (cut, then fence) is a new sanitizer in
`.semgrep/fence-untrusted-data.yml`, beside `_wrap_analytics` and `_envelope`.
A canary check confirms the rule still flags an unfenced return, and also a
result that was cut but not fenced. The function is registered in
`tests/security_reviews.json`.

## Compact JSON tool output

Eight return paths sent pretty-printed JSON (`indent=2`) to the model:
`find_tool`, `validate_kql`, `self_check`, `generate_parser`,
`review_generated`, and the CanonLoom bridge tools. They now use compact
separators. On a `find_tool` answer this is 32% fewer characters. The content
is the same.

CLI output (`--doctor`, the `--export-bi` manifest, `--agent-report-json`) and
the HTML dashboard stay pretty-printed, because people read them.

## Bounded result cache and fail-cooldown table

An expired cache entry used to stay until the same query came back. A
long-running server (the HTTP transport) therefore kept every distinct result
it had answered. The fail-cooldown table had the same problem.

Each insert now removes expired entries, then removes the oldest beyond
`BERSERK_MCP_CACHE_MAX_ENTRIES` (default 256). This is a bound, not a switch:
`0` means the default.

## Upgrade notes

- New settings: `BERSERK_MCP_MAX_OUTPUT_CHARS`, `BERSERK_MCP_CACHE_MAX_ENTRIES`.
  See [configuration](../configuration.md).
- A client that parsed the exact whitespace of the eight JSON outputs must
  parse them as JSON instead.
- Tests: `tests/test_output_budget.py` (19 tests). Three of them call
  through `dispatch()`, where the output redactor runs, and check that
  credentials are still removed from the compact JSON. With redaction
  switched off they fail, so they detect a leak.
