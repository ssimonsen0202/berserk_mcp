# v1.20.0 — 2026-07-24

Adds schema-grounded, cost-aware KQL validation for custom and generated
queries.

## What changed

- New `validate_kql` MCP tool for `sre`, `soc`, `claude`, and `ops` roles.
  Static mode checks query shape without executing the user query. Live mode is
  opt-in with `BERSERK_MCP_KQL_LIVE_VALIDATION=1` and returns a runtime receipt.
- New stdlib modules:
  - `kql_validation.py` for deterministic static findings, risk scoring, and
    defensive CLI stats parsing.
  - `schema_registry.py` for normalized schema snapshots, stable schema hashes,
    compact local-model context, field suggestions, and safe cache recovery.
- Arbitrary `search`, `save_query`, `run_saved`, and generated parser
  persistence now run validation. Default `warn` mode preserves existing
  workflows while rejecting malformed/control-command input and reporting
  performance risks.
- Saved queries now record validation metadata: version, risk, schema hash,
  schema status, and validation timestamp. Legacy entries remain runnable.
- Parser-factory prompts receive compact schema context and a schema hash, and
  generated candidates must pass static validation before execution and save.
- Interactive query execution has a bounded per-process concurrency guard via
  `BERSERK_MCP_MAX_CONCURRENT_QUERIES`.

## Compatibility

Default mode is `BERSERK_MCP_KQL_VALIDATION=warn`. Existing fixed tools keep
their normal output. Arbitrary `search` may include validation warnings, and
queries with blocking syntax/control-command findings are rejected before
`bzrk` is called.

Use `strict` to block high-risk arbitrary/generated queries. Use `off` to
disable automatic validation and concurrency enforcement for compatibility;
the explicit `validate_kql` tool still works.

Runtime stats are never fabricated. If the local `bzrk` build does not return a
supported `--stats` format, live validation reports local duration and
`STATS_UNAVAILABLE`.
