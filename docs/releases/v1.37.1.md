# v1.37.1 — Null-trap guidance in `search`

Released: 2026-10-04

## What changed

The `kql` argument of the `search` tool now warns about a KQL trap. KQL
follows three-valued logic. For a row where `x` is null, `x > 5` is null, and
so is `not(x > 5)`. A `where` clause drops null rows. A query such as
`where not(x > 5)` therefore leaves out every row where `x` is missing, and
the answer looks complete but is short.

The description now says to add `or isnull(x)` to keep those rows. It closes
issue #36.

## Why

A model that writes a negation has no reason to suspect that rows vanish. A
short note in the tool description costs a few tokens and prevents a silent
wrong answer. This is one of the wrong-answer controls in
[`docs/wrong-answer-containment.md`](../wrong-answer-containment.md).

## Verification

`test_search_kql_arg_warns_about_kleene_null_trap` checks the description. It
failed before the change and passes after it. The full suite passes.

This is the one change from the old PR #94 that `main` did not already have.
The other four commits in that PR were the egress work that v1.34.0 ported
onto current code.
