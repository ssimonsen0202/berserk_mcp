# v1.22.0 — Security remediation Phases 0–2

Released 2026-07-27.

This release implements the approved foundation and first two phases of the
2026-07-27 security review. It remains standard-library-only and preserves the
default `BERSERK_MCP_KQL_VALIDATION=warn` product policy.

## Query and process boundary

- Query concurrency is independent of validation mode; `off`, `warn`, and
  `strict` all acquire and release the configured semaphore correctly.
- The final `bzrk` boundary rejects semicolons and control commands before
  process creation. Static KQL validation also blocks source-introducing
  operators.
- `bzrk` stdout and stderr are drained incrementally. Successful output is
  capped by `BERSERK_MCP_MAX_RESULT_BYTES` (10 MiB by default); overflow and
  timeout paths kill and reap the child.
- `BZRK_BIN` resolves once to an absolute executable path. Windows rejects a
  bare name planted in the MCP client's working directory.
- Every interpolated identifier and search term now has explicit character and
  length bounds.
- An AST regression test protects the no-shell/no-eval/no-string-argv contract.

## FinOps data integrity

- Secret and PII redaction is always applied to FinOps payloads.
- Valid governed IDs remain stable across MCP output, dashboards, BI exports,
  and recommendation decisions.
- `BERSERK_MCP_FINOPS_REDACT_ENTROPY=1` enables entropy filtering for free text
  without non-deterministically destroying valid join keys.

## Shared stores and permissions

- `_store.py` is now the only implementation of path validation, atomic writes,
  JSON stores, unique temp files, and portable lockfiles.
- Private stores use `0600` files and process-created `0700` directories on
  POSIX. Windows uses a protected current-user-only DACL.
- Existing directory permissions are never changed. BI and management-report
  publication targets retain operator-owned access policy.
- Schema caches and AI FinOps outputs now receive the same absolute-path,
  traversal, and control-character validation as the learned-query store.
- The 30-second stale-lock break remains by design; its suspended-process
  lost-update risk is documented in `SECURITY.md`.

## Shared outbound HTTP

- `_http.py` now serves LLM providers, Hermes discovery, OTLP, Discord alerts,
  and the router eval harness.
- All callers validate URLs and headers, block redirects, and bound responses.
- Non-loopback OTLP endpoints require HTTPS. Malformed OTLP header items fail
  loudly and cannot override JSON `Content-Type`.
- Eval provider errors no longer echo response bodies, and MCP startup stderr is
  surfaced when the eval handshake fails.

## Primer configuration

An explicit `BERSERK_MCP_PRIMERS_DIR` must be an absolute validated directory.
For an active role it must contain a readable `<role>.md`; otherwise startup
fails with a clear error instead of silently dropping role guidance.

## Verification

The release adds focused regression coverage for each boundary above. Both
supported suite entry points run offline:

```bash
python tests/test_berserk_mcp.py
python -m unittest discover -s tests
```
