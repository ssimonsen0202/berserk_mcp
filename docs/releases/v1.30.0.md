# v1.30.0 — Security hardening, small-tier consistency, and evidence-bearing results

Released: 2026-09-26

This release collects the work since v1.29.1: the fixes from a Codex Security
scan, the implementation plan from the MCP guidance review
([`docs/mcp-guidance-review-2026-09-26.md`](../mcp-guidance-review-2026-09-26.md)),
new CI gates, and eval improvements. Every change was reviewed by Codex before
it was committed, and CI passed on Ubuntu and Windows with Python 3.9, 3.11
and 3.12.

## Upgrade notes

Read these before you upgrade. Several changes are deliberately stricter.

- **Generated queries need approval.** A query the parser factory generates is
  now stored as pending. The small tier cannot see or run it until an operator
  runs `berserk-mcp --approve-generated <name>`. Generated queries already in
  your store have no status, so they count as pending too: approve the ones
  you want in operational lanes. The approval gate does not apply to the deep
  tier; role scoping still does.
- **Unknown tool arguments are rejected.** `tools/call` returns an error that
  names the unknown argument and lists the valid ones. Before, the server
  ignored it, so a misspelled filter silently widened the query. Only
  `as_task` and `allow_expensive` are accepted without a schema entry.
- **User KQL cannot read other tables.** The execution boundary now refuses
  source operators and functions (`union`, `join`, `lookup`, `evaluate`,
  `invoke`, `toscalar(`, `table(`, and similar) in every validation mode, and
  requires the right operand of `in`, `has`, `has_any` and related operators
  to be a literal. A column-to-column comparison such as `where x has y` is
  refused too.
- **Small-tier guidance changed.** Small-tier lanes no longer receive the
  `search` / `save_query` / KQL-authoring guidance, because that tier hides
  those tools. If you keep your own primers in `BERSERK_MCP_PRIMERS_DIR`, end
  each deep-only line with `<!-- deep-tier -->`; startup warns when an active
  primer still names a hidden tool.
- **The result header has more fields.** Fixed-query results now start with
  `window=… rows=… source=… redaction=… at=… ref=…`. The rows below it are
  unchanged. `BERSERK_MCP_ENVELOPE=0` still restores the old output.
- **Plaintext OpenRouter forwarding needs an opt-in.** The OpenRouter webhook
  receiver and backfill refuse a plaintext `http://` endpoint that is not on
  loopback unless you pass `--allow-plaintext-remote`.

## Security

- Closed three findings from a Codex Security scan of the query and process
  boundary: user KQL reading other tables, entity-encoded tags escaping the
  untrusted-data fence, and a late authentication error reported as an empty
  result. The fence now decodes HTML, JSON and URL escapes before matching,
  in all three fences (telemetry, saved-query descriptions, parser samples).
- Redaction: quoted and bare credential forms, `github_pat_` tokens, and a
  linear private-key scan with fail-closed limits.
- Outbound HTTP: loopback requests never use a proxy; plaintext to a remote
  host needs an explicit opt-in per service; OTLP and CanonLoom always need
  HTTPS off loopback.
- The final KQL execution boundary moved into its own module,
  `_kql_boundary.py`, so it can be reviewed and scanned alone.

## Small models and routing

- Instructions, primers, tool descriptions, saved-query descriptions and
  empty-result next steps no longer name a tool the lane or tier hides. A test
  checks every surface for every lane and tier.
- The advertised `since` pattern shrank from 377 to 59 bytes. It still
  accepts every form the server accepts, in any letter case. Real-model runs
  measured about 47% fewer input tokens per request, with no accuracy change.
- The error-rate investigation checks that logs are arriving before it
  reports "no errors", and reports the previous window's error rate as
  context. Its branching still uses the SRE primer's fixed threshold.

## CI and tests

- New fail-closed gates: pinned Trail of Bits semgrep rules over every
  tracked file (with a canary check), SECURITY.md section coverage, and an
  expiring security-review registry.
- CI now runs the eval and ingestion test suites.
- A CI `lint` job: ruff (with a complexity cap, plus the format check) and
  mypy over all 17 shipped modules, with pinned tool versions. Coverage is
  configured and runs locally.

## Evals

- New case sets: near-miss, confusable pairs, `since` values (scored for
  server validity), and tier-specific answers.
- Lane runs (`BERSERK_MCP_ROLE` / `BERSERK_MCP_TIER`) report a case whose
  expected tool the lane does not serve as not applicable, not as a miss.
- A case can name a different expected answer for a lane that hides its
  primary tool (`expect_tool_when_hidden`) and extra acceptable answers
  (`also_accept`). `run_eval.py --saved-queries FILE` serves a fixture store,
  so `saved__*` answers can be tested.
- The ledger records a `tool_schema_version`, so a description edit is not
  mistaken for model drift.
