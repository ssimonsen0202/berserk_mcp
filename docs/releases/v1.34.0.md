# v1.34.0 — Optional egress policy and connect-time address checks

Released: 2026-09-26

Ports the security controls of the unmerged `feat/local-only-egress-hardening`
branch (16–17 September) onto the current code. The branch itself was not
merged: it forked before the v1.29.0 refactor and carries a conflicting
v1.29.0. Two of its controls were already on `main` (proxy-free loopback
requests, the no-redirect quota opener) and its `approve_generated_query` tool
is replaced by the CLI-only `--approve-generated` of v1.30.0.

## What changed

- **Egress policy (opt-in).** `BERSERK_LOCAL_ONLY=1`,
  `BERSERK_EGRESS_ALLOWED_HOSTS` or `BERSERK_EGRESS_ALLOWED_CIDRS` activates a
  destination policy for every outbound call: LLM providers, Hermes and its
  model discovery, CanonLoom, Discord, OTLP, the doctor probes and the quota
  endpoint. Only loopback, hosts listed by name, and addresses inside the
  listed networks are reachable; anything else is refused before any request
  is sent. An invalid or allow-everything network (`0.0.0.0/0`) fails closed.
  While the policy is active, ambient `HTTP(S)_PROXY` settings are ignored,
  since a proxy would hide the real destination.
- **Local-only LLM ladder.** Under `BERSERK_LOCAL_ONLY`, the OpenAI and
  Anthropic providers are refused even when their API keys are set, so an
  inherited key cannot silently re-enable cloud generation. The cloud LLM
  hosts (`api.openai.com`, `api.anthropic.com`, `openrouter.ai`) are refused
  under local-only even if an allowlist names them, for the eval harness too.
  That list cannot name every cloud endpoint; the allowlist is the real
  guarantee, so do not list a cloud endpoint you do not want reached. The quota
  endpoint falls back to its log-derived estimate.
- **Connect-time address checks (DNS pinning).** Every outbound connection
  resolves its host once and connects only to addresses that were checked:
  a host treated as loopback (such as `localhost`) must resolve to loopback,
  and under the policy a hostname not listed by name is connected only to
  those of its addresses inside the approved networks (refused if none are). The TLS certificate and SNI are still checked against
  the original hostname. The branch's version pinned the address without
  checking it; this one checks it.
- **Management-token gate.** When `BERSERK_MCP_MGMT_TOKEN` is set,
  `save_query` requires a matching `mgmt_token` argument (constant-time
  comparison, read on every call).
- **Doctor probes.** At most two reachability probes can run at once, so
  repeated `self_check` calls against a hung endpoint cannot pile up threads.
  `--doctor` has a new `egress_policy` check showing the effective policy.

## Upgrade note

Nothing changes unless you set the new variables. If you do, list every
non-loopback integration host (Hermes, CanonLoom, Discord, OTLP collector) in
`BERSERK_EGRESS_ALLOWED_HOSTS` or its network in `BERSERK_EGRESS_ALLOWED_CIDRS`,
then run `berserk-mcp --doctor` to see the effective policy.

## Testing

`tests/test_egress_policy.py`: policy decisions (inactive, local-only,
by-name, by-network, bad configuration, malformed URLs), connect-time checks
with controlled DNS answers, a real HTTP request (one resolution, original
`Host` header), a refused `localhost` that resolves elsewhere, an HTTPS server
with a test certificate (verified against the hostname; a name the
certificate does not cover is rejected), the local-only LLM and quota
refusals, the doctor report, the probe limit, and the token gate.
