# v1.37.12 — carry failure history up the author ladder

Released: 2026-11-17

## What changed

- **The gap.** Each provider on the author ladder started with no knowledge of
  earlier failures. A later model could repeat a mistake an earlier model had
  already made.
- **The change.** `_run_provider_ladder` keeps a history. Each provider that
  generated something and failed validation adds one note:
  `"<provider>: <errors joined with '; '>"`. The history holds at most three
  notes, newest last.
- **No note without a reply.** A provider that fails before it generates
  anything adds no note. This covers an LLM error or a model-lookup error on
  its first attempt.
- **Redaction.** Every note goes through `_safe_diag_text(note,
  FEEDBACK_ERROR_CAP)` when the ladder builds it. Parse errors and query names
  are model-written text, so they are redacted as well. One note is never
  longer than `FEEDBACK_ERROR_CAP`.
- **Prompt block.** The first prompt to a later provider gets an
  `<earlier-attempts>` block. The block is fenced with the same tag guard as
  sample data, so a forged closing tag cannot end it early. The block comes
  before that provider's own refinement feedback.
- **Unchanged.** Per-provider refinement feedback works as before. The total
  attempt budget (`MAX_TOTAL_ATTEMPTS`) and the job deadline do not change.
  The ladder makes no new outbound call.

## Verification

`tests/test_parser_factory.py` adds six tests. Each failed before the change.
They cover the prompt block, the three-note and length bounds, providers that
fail before they generate, a forged closing tag, and redaction of a secret in
a parse error and in a query name.
