# v1.37.6 — Test-only baseline for the learning-loop work

Released: 2026-11-16

This release changes no server behaviour. It fixes the starting point for the
learning-loop work, so that a later failure points to the change that caused it.

## What changed

- **Root-safe doctor test.** `test_learned_store_writable_fail_when_parent_not_writable`
  sets a directory to mode `0o500` and expects a write to fail. Root ignores
  that mode, so the test failed in a root sandbox. The test now skips when the
  effective user is root. The skip message gives the reason.
- **Legacy store fixture.** `tests/fixtures/learned_legacy_v1_37.json` holds a
  learned-query store as v1.37.5 writes it. It has one manual entry, one
  generated entry that awaits approval, one generated entry that an operator
  approved, and one manual entry scoped to a role. The v1.37.5 code produced it:
  `save_query`, `persist_learned_query` with `action_source="generated"`, and
  `approve_generated_query` ran against a temporary store with `bzrk` stubbed.
  No one wrote the file by hand.
- **Compatibility test.** `tests/test_learned_legacy_compat.py` copies the
  fixture to a temporary store and pins today's behaviour in both tiers:
  - which `saved__*` tools `tools/list` shows, the
    `<generated-description>` fence, and the `since`-only input schema;
  - which entries `list_saved` shows, and that another role does not see a
    role-scoped entry;
  - that `run_saved` and `saved__<name>` run a visible entry, and refuse a
    pending generated entry in the small tier and a role-hidden entry;
  - that reading and running leave the store file unchanged.
- **Older store shapes.** The same test adds two entries by hand that v1.37.5
  reads but no longer writes: a generated entry with no `status`, and one with
  `generated_by` but no `origin`. Both count as generated and awaiting approval,
  so the small tier does not see them.

## Verification

The new tests pass on the unchanged server code. Every later learning-loop
change must keep them green.
