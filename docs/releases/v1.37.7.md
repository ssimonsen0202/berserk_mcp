# v1.37.7 — Fence every generated saved-query description

Released: 2026-11-17

## What changed

- **Fence check matches the visibility check.** `config.is_generated` treats a
  saved query as generated when it has `origin: "generated"` or a
  `generated_by` block. The small tier hides both kinds until an operator
  approves them. The description fence checked `origin` alone, so an entry with
  `generated_by` and no `origin` reached `tools/list` and `list_saved` with its
  model-written description unfenced. Both places now call `is_generated`.
- **Who could see it.** Only the deep tier, and only for stores written by older
  versions: the current code always writes `origin` on a generated entry.

## Not changed

Eviction and the `_gen` rename still test `origin` alone. For such an entry they
act as if a human wrote it, which protects it. That is the safe direction.

## Verification

`tests/test_learned_legacy_compat.py` gains
`test_older_no_origin_entry_is_fenced_in_tools_list_and_list_saved`. It failed
before the fix and passes after it.
