# v1.37.7 — Fence every generated saved-query description

Released: 2026-11-17

## What changed

- **Fence check matches the visibility check.** `config.is_generated` treats a
  saved query as generated when it has `origin: "generated"` or a
  `generated_by` block. The small tier hides both kinds until an operator
  approves them. The description fence checked `origin` alone, so an entry with
  `generated_by` and no `origin` reached `tools/list` and `list_saved` with its
  model-written description unfenced. Both places now call `is_generated`.
- **Forged tags in `list_saved` and `review_generated`.** Both wrapped the raw
  description in the fence, so a description holding its own
  `</generated-description>` ended the fence early. Both now use the same
  sanitiser as `tools/list`: redaction, tag neutralisation, angle brackets
  replaced, cut to 240 characters. This applies to every saved query, which
  also shortens long descriptions in `list_saved`.
- **`review_generated`.** It now lists every entry `is_generated` accepts,
  fences the JSON it returns for one entry as untrusted data, and no longer
  fails on a `generated_by` value that is not an object.
- **Who could see it.** Only the deep tier, and only for stores written by older
  versions: the current code always writes `origin` on a generated entry.

## Not changed

Eviction and the `_gen` rename still test `origin` alone. For such an entry they
act as if a human wrote it, which protects it. That is the safe direction.

## Verification

`tests/test_learned_legacy_compat.py` gains four tests: the `generated_by`-only
fence in `tools/list` and `list_saved`, forged tags in `list_saved`, and both
`review_generated` paths. Each failed before the fix and passes after it.
