# v1.37.14 — usage statistics and a ranked projection

Released: 2026-11-17

## What changed

- **Usage file.** `usage_stats.json` sits beside `learned.json`. For each saved
  query it holds `calls`, `last_called`, `rows_calls`, `zero_row_calls`,
  `error_calls` and `last_rows_at`. The module is `berserk_mcp/usage.py`. All
  file access goes through `_store`. The file is private (mode 0600).
- **Recording.** `run_saved` and the `saved__*` tools share `_run_saved_entry`.
  After the query runs, it records `rows`, `empty` (zero rows) or `error`.
  `usage.record` waits at most one second for its lock. On any error it logs and
  returns, so a usage failure never fails or delays a tool call. Keys are
  sanitised names only. The file holds at most 500 entries and drops names that
  the store no longer holds.
- **Lock order.** The usage lock and the learned-store lock are never held
  together. Readers of the usage file take no lock.
- **Ranked projection.** `_saved_query_tools` no longer takes the last N
  entries. It ranks by calls, then `last_called`, then store position (later
  first). When human-written entries exist, they keep at least half the cap,
  rounded up. Spare reserve slots go to the other entries. The chosen tools are
  listed in rank order. `BERSERK_MCP_SAVED_TOOL_CAP=0` still disables the
  projection. With no usage, the order is newest first.
- **Stable order.** The ranking is recomputed when the store file changes, when
  the role, tier or cap changes, or when the cached ranking is older than 3600
  seconds. A usage write alone never changes `tools/list` and never sends
  `notifications/tools/list_changed`.
- **Discovery mode.** `tools/list` lists the first `BERSERK_MCP_DISCOVERY_SAVED_CAP`
  entries of the ranked projection, not the most recent ones.
- **`list_saved`.** Each line, with or without `query`, ends with
  `(calls=N, last_called=...)`. This is server text outside the fence. It holds
  counters and a validated timestamp only.
- **Eviction by usage.** At the 500-entry cap, `_make_room` removes the least
  used entry: fewest calls, then oldest `last_called`, then oldest position.
  Entries never called go first. A human write removes generated entries before
  human ones. A generated write still never removes a human entry, and the new
  entry is never the one removed.
- **Visible entries only.** Eviction may remove only an entry that
  `config.item_visible` accepts for the writing role and tier. If none can go,
  the save is refused and nothing is written. `save_query` returns an error
  that starts with `NOT saved`. A generated write fails the same way and the
  worker reports `needs_human`. The check runs inside the store lock.
- **Empty results.** For an entry verified before, the empty-result text adds
  `It last returned rows at <time>.` before `Try since='24h ago'.` The time comes
  from `usage_stats.json`. It is shown only when it is a valid timestamp.

## Not in this release

The exclusion of entries with `health == "stale"` waits for the health check
(WP11). There is no `health` field yet.

## Behaviour changes to know

- `tools/list` now lists saved tools best-ranked first. Before, it listed them
  oldest first. With no usage data, that is newest first.
- A manual write at the cap removes the least-used visible entry, not the
  oldest.

## Configuration

No new environment variable.

## Verification

`tests/test_usage_stats.py` holds the WP4 tests. Each failed before the change.
Two tests in `tests/test_tool_discovery_saved.py` changed to the new list order.
