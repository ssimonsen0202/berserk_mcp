# v1.31.0 — Python 3.11 minimum

Released: 2026-09-26

## Upgrade note

**berserk-mcp now requires Python 3.11 or later** (`requires-python =
">=3.11"`). pip refuses to install it on Python 3.9 or 3.10. Before you
upgrade a host, check its interpreter:

```bash
python3 --version
```

If it is older than 3.11, install a newer Python and rebuild the host's
virtual environment with it, then reinstall berserk-mcp. The project has no
third-party runtime dependencies, so nothing else needs upgrading.

## Why

- Python 3.9 reached end of life in October 2025 and no longer receives
  security fixes. Python 3.10 reaches end of life in October 2026.
- mypy 2.x cannot check code as Python 3.9, so the type check ran against
  3.10 while the project claimed 3.9. It now checks as 3.11, the real floor.
- CI now tests the versions people run: 3.11, 3.12, 3.13 and 3.14, on Ubuntu
  and Windows (8 test jobs). The 3.9 jobs are gone.

## What changed in the code

Nothing a caller can see. Raising ruff's target to Python 3.11 enabled a few
lint fixes, all behaviour-preserving:

- `datetime.timezone.utc` became `datetime.UTC`.
- `datetime.fromisoformat` no longer needs a `"Z"` to `"+00:00"` rewrite
  first; Python 3.11 parses `Z` directly. Checked on 3.11 against nine
  inputs, including 7-digit fractions and invalid strings: identical results.
- `zip()` calls state `strict=` explicitly: `strict=False` where lengths may
  differ on purpose (parsing a Kusto row, pairwise loops), and `strict=True`
  in one eval helper where they match by construction.
- The packaging test lost its Python 3.9 fallback TOML parser, now that
  `tomllib` is always available.

All suites passed locally on Python 3.11.15 and 3.14.7 before release; CI
runs them on 3.11, 3.12, 3.13 and 3.14.
