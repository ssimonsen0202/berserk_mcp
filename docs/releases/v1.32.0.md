# v1.32.0 — DNS-rebinding protection on by default

Released: 2026-09-26

Closes [issue #84](https://github.com/ssimonsen0202/berserk_mcp/issues/84),
the one open finding from the 2026-08-29 run of the official MCP conformance
suite ([docs/mcp-conformance.md](../mcp-conformance.md)).

## The problem

The optional HTTP transport (`BERSERK_MCP_HTTP_ENABLE=1`) binds to loopback
by default, but with no `BERSERK_MCP_HTTP_ALLOWED_HOSTS` it accepted any
`Host` header. A web page open in a browser on the same machine could point
its own domain at 127.0.0.1 (DNS rebinding) and call the server's `/mcp`
endpoint, receiving real responses. The conformance suite's
`dns-rebinding-protection` scenario failed for exactly this reason.

## What changed

- **Host allowlist on by default for a loopback bind.** With no explicit
  `BERSERK_MCP_HTTP_ALLOWED_HOSTS`, a loopback-bound server accepts only
  `localhost`, `127.0.0.1`, `::1` and the bound host. Anything else gets 403.
- **Origin check.** When a request carries an `Origin` header (browsers send
  one on cross-origin requests), its host must also be allowed; `Origin:
  null` is refused. Non-browser MCP clients normally send no `Origin` and
  are unaffected.
- An explicit `BERSERK_MCP_HTTP_ALLOWED_HOSTS` is used exactly as given, as
  before. Non-loopback binds still require it.
- **Strict `Host` parsing.** Only `host[:port]` (or `[ipv6]:port`) is
  accepted; one trailing dot is ignored (`localhost.` is `localhost`).
  A malformed value such as `127.0.0.1:8765@evil` gets 403, a request with
  two `Host` headers gets 400, and one with two `Origin` headers gets 403.

## Upgrade note

If a client reaches a loopback-bound server under another name (for example
a custom `/etc/hosts` alias), add that name to
`BERSERK_MCP_HTTP_ALLOWED_HOSTS`. The stdio transport is unaffected.

## Testing

`test_issue_84_default_loopback_config_rejects_a_rebinding_host` replays the
conformance repro against a real server: a spoofed `Host`, a foreign
`Origin` and `Origin: null` get 403; `localhost`, `127.0.0.1` and a loopback
`Origin` get 200. Run against the previous code, the same test fails with
200 for all three hostile requests. The HTTP protocol smoke test passes.
