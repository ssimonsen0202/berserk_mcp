# v1.25.1 — KQL performance guardrails

Released: 2026-08-11

v1.25.1 fixes costly default query shapes and adds regression protection so
future shipped queries are evaluated by the same static validator exposed to
users.

## Fixes

- Filter `list_services` to log and metric rows before aggregation, matching
  the tool's declared log/metric breakdown.
- Limit unfiltered resource fieldstats to depth 1. Service-filtered discovery
  retains depth 2.
- Validate every shipped `SIMPLE` query plus filtered and unfiltered fieldstats
  in the test suite. Intentional findings require exact, reasoned allowlist
  entries, and stale exceptions fail the test.
- Derive query-budget headroom from static risk at startup: low-risk queries
  use 1x base budget, medium-risk queries 1.5x, and high-risk queries 2x before
  time-window scaling and the global timeout cap.

## Verification

- The full unit suite passes with 597 tests and 1 skip.
- Live default-window checks against the deployment profile completed for
  `list_services`, `list_metrics`, and `discover_schema` without retries or
  budget overrides.
