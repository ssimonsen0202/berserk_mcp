# v1.37.0 — Package split

Released: 2026-10-03

## What changed

The server code was one 6,165-line file, `berserk_mcp.py`. It is now the
`berserk_mcp/` package. No module is over 1,200 lines.

The modules form layers. A module may import only the layers below it.
The list runs from the lowest layer to the highest.

| Layer | Module | Lines | Holds |
| --- | --- | --- | --- |
| 1 | `_version` | 3 | The version string. |
| 2 | `config` | 955 | Environment settings, shared state, small helpers. |
| 3 | `fencing` | 154 | Untrusted-data fences and output caps. |
| 4 | `queries` | 539 | Verified KQL queries and their builders. |
| 5 | `runner` | 536 | Bounded `bzrk` subprocesses, search, schema, KQL validation. |
| 6 | `tools` | 478 | Tool definitions and the text the model reads. |
| 7 | `learned` | 412 | The learned and saved query store, sibling wiring. |
| 8 | `httpconfig` | 232 | HTTP transport settings. |
| 9 | `doctor` | 635 | The `--doctor` and `self_check` preflight, admin commands. |
| 10 | `handlers.tail` | 128 | Tail and CanonLoom handlers. |
| 11 | `handlers.learning` | 266 | Learning loop, jobs, discovery handlers. |
| 12 | `handlers.diagnostics` | 385 | Diagnostics, model drift, parser handlers. |
| 13 | `handlers.search` | 267 | Query, search, analytics, FinOps handlers. |
| 14 | `handlers.dispatch` | 240 | Tool-call dispatch, fleet budget, cache, cooldown. |
| 15 | `server` | 989 | JSON-RPC plumbing, stdio and HTTP transports. |
| 16 | `cli` | 439 | Command-line entry point, scheduled passes. |

The facade is `berserk_mcp/__init__.py` (66 lines). `berserk_mcp.NAME` reads
and writes `NAME` in the module that owns it. Reads resolve at call time, so
a value that a module changes at run time is never stale. Writes, including
`unittest.mock.patch.object`, land in the owning module.

The launcher is the root `berserk_mcp.py` (10 lines). It starts the server.

## Why

One file this size was hard to review, hard to scan for security flaws, and
slow to change without merge conflicts.

## Compatibility

Behavior does not change.

- `python3 berserk_mcp.py` still starts the server.
- `python3 -m berserk_mcp` also starts the server.
- The installed entry point is `berserk-mcp = "berserk_mcp.cli:main"`.
- `berserk_mcp.NAME` still works for every public name, through the facade.
- The keys in `tests/security_reviews.json` are now
  `berserk_mcp.<module>:<function>`. They were `berserk_mcp:<function>`.
- Install with `pip install .` or a built wheel. Do not copy the launcher
  alone: it needs the `berserk_mcp/` package.

## Verification

- The unit suite passes on Python 3.11 and 3.14 locally. It also passes on
  the CI matrix: Ubuntu and Windows, Python 3.11 to 3.14.
- `mypy`, `ruff` and `semgrep` pass. The new semgrep rule test passes.
- An AST pure-move comparison checked each slice. Each function moved without
  a change to its code.
- A byte-for-byte parity check compared `initialize`, `tools/list` and 12
  tool calls against `main`. All matched.
- Codex Security review 1 (scan `20261003T195944Z-81942`) covered `config`,
  `fencing`, `runner`, the facade and the semgrep rule. It reported one low
  finding that the split caused: the semgrep sanitizer patterns accepted any
  receiver, and `_wrap_analytics` was modeled as a fence. Commit 9177ccb
  fixed it.
- The same review reported three medium findings. They predate the split.
  They are tracked for a follow-up release:
  - Direct `run_bzrk` callers outside the query semaphore.
  - The process-global fleet context.
  - Unfenced telemetry in `scan_secrets`, `detect_new_sources` and `self_check`.
- Codex Security review 2 covers the rest of the package. Review 2: pending.
