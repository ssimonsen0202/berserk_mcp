# v1.29.0 — Sovereign deployment hardening (local-only egress policy)

Released: 2026-09-17

## Why we built this

berserk-mcp already hardened its outbound HTTP (no-redirect opener,
TLS-by-default for remote hosts, bounded responses). But a
sovereignty-constrained deployment — air-gapped, defense, or regulation-
driven — needs a stronger guarantee: **no unapproved non-loopback egress
at all**, not just safe egress. An inherited `HERMES_API_KEY` or
`ANTHROPIC_API_KEY` in the environment could silently re-enable cloud
fallback, and there was no mechanism to prevent it.

The same gap applied to the live quota endpoint (`claude_quota_status`),
which sent an OAuth bearer token to `api.anthropic.com` through a direct
`urllib` call that bypassed every policy check.

## What changed

### New feature: opt-in local-only mode

- **`BERSERK_LOCAL_ONLY=1`** refuses cloud LLM providers (OpenAI, Anthropic)
  for the generation ladder and any direct `llm_complete()` call, even if
  their API keys are present. It also activates a destination allowlist for
  every outbound integration: Hermes, CanonLoom, Discord, the eval harness,
  and the live quota endpoint.
- **`BERSERK_EGRESS_ALLOWED_HOSTS`** — comma-separated approved non-loopback
  hostnames. Setting this (or `_CIDRS`) opts into the restrictive policy
  even without `BERSERK_LOCAL_ONLY`.
- **`BERSERK_EGRESS_ALLOWED_CIDRS`** — comma-separated approved non-loopback
  networks (CIDR notation). Same activation rule.
- Loopback is always allowed. `berserk-mcp --doctor` shows the effective
  policy.

### Security hardening (6 controls)

- **DNS-rebinding-resistant connection pinning.** `_PinnedConnectionMixin`
  resolves the hostname once at connect time and pins the socket to that IP
  for the life of the connection. A DNS rebind after the initial resolution
  cannot redirect the request to a different host.
- **No-inherited-proxy isolation.** `ProxyHandler({})` in the shared opener
  disables ambient `HTTP_PROXY` / `HTTPS_PROXY` handling entirely, so an
  environment variable set for an unrelated purpose cannot redirect
  berserk-mcp's outbound traffic through an unexpected proxy.
- **Management-token gate.** `BERSERK_MCP_MGMT_TOKEN` gates both
  `save_query` and `approve_generated_query`. When set, callers must pass its
  value as the `mgmt_token` argument. When unset, the tools work as before
  (backwards-compatible). Uses `hmac.compare_digest` for constant-time
  comparison; the token is read fresh from `os.environ` on every call.
- **Bounded doctor-probe concurrency.** `_DOCTOR_PROBE_SEMAPHORE` (2 slots)
  prevents thread/socket leakage from `_with_wall_clock_timeout` across
  repeated `self_check` calls. Thread-creation failure releases the semaphore
  before re-raising.
- **Egress-policy enforcement on live quota endpoint.** `_fetch_live_usage()`
  now calls `validate_http_url()` and `validate_egress_destination()` before
  opening the connection. A blocked endpoint degrades to the log-derived
  estimated path — the existing fallback.
- **Empty-cases guard in the eval harness.** Prevents division-by-zero when
  the cases file is empty or `--limit` filters it to zero.

### New tool

- **`approve_generated_query`** — promote a generated parser to active
  status, or revoke its trust. Gated by the management token when set.

### Bug fixes

- **Missing `_KNOWN_MUTATING_TOOLS` / `_MUTATION_SOURCE_MARKERS` /
  `_dispatch_blocks_from_source()` / `_mutating_tools_from_dispatch_source()`
  definitions.** These were referenced by `_annotation_catalog_violations()`
  (already on main) but never defined — a genuine pre-existing `NameError`
  on `--doctor` / `self_check`.
- **`_doctor_check_llm_reachability` egress validation.** Added missing
  `validate_egress_destination()` check on both the discovery-URL success
  path and the direct-probe path (when discovery is bypassed).
- **Cross-platform `ConnectionError` handling in deadline test.** Windows
  surfaces an abrupt connection close as `ConnectionAbortedError` (not
  `ConnectionResetError`); broadened the catch to `ConnectionError`, the
  common base.

## Review process

Eighteen rounds of Codex adversarial review across two sessions, each
finding independently verified against real code before fixing. The last
round's finding (quota-status egress bypass) was the only genuine new
issue; the preceding seventeen rounds cycled a single
deliberately-rejected authorization finding (management-token gate) until
the user chose to fix it, then verified clean.

## Test coverage

1108 tests, all passing on Ubuntu (3.9/3.11/3.12) and Windows
(3.9/3.11/3.12). New tests cover every control: local-only blocking,
allowlist pass-through, loopback exceptions, management-token enforcement,
DNS-rebinding pinning, proxy isolation, probe-semaphore bounds, and
quota-endpoint egress policy.
