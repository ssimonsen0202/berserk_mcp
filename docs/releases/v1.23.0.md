# v1.23.0 — Security remediation Phase 3

Released 2026-07-27.

This release completes the approved Phase 3 medium-severity findings from the
2026-07-27 security review. It remains standard-library-only and preserves the
existing query and API behavior unless a boundary needed stricter output or
persistence handling.

## Generated and model-facing content

- LLM-generated saved-query descriptions are normalized, stripped of control
  characters and backticks, and capped before persistence (SR-06). Generated
  `since` defaults must pass the same bounded grammar as runtime input.
- Imported or telemetry-derived backtick runs are broken before JSON or
  Markdown is placed inside model-facing fences (SR-13). Fence length is also
  selected from the sanitized payload, preventing attacker-controlled data
  from terminating a block and becoming adjacent instruction-like prose.
- Discord alerts receive mandatory secret and PII redaction at the final
  egress boundary before transport truncation, even when the general MCP
  output mode is configured as `flag` or `off` (SR-15).

## FinOps privacy and export safety

- Feature and recommendation-decision owner identifiers are replaced before
  persistence with stable HMAC-SHA256 pseudonyms (SR-11/SR-25). A deployment
  can supply `BERSERK_MCP_PSEUDONYM_KEY`; otherwise a random private key is
  generated in the per-user configuration directory.
- Legacy clear-text owner identifiers are scrubbed in memory before dashboard,
  report, or BI export generation. Pseudonyms remain personal data and still
  require appropriate authorization, retention, and deletion controls.
- CSV exports neutralize string cells beginning with spreadsheet formula
  characters while preserving numeric values (SR-12). NDJSON remains the
  lossless format when downstream consumers require the original strings.

## Public artifacts and dashboards

- Tracked public documentation, dashboard examples, evaluation plans, and
  catalogs no longer expose deployment-specific hostnames, service-unit names,
  private profile names, or live session identifiers (SR-09). A regression
  test scans the tracked publication surface for known markers and UUID-shaped
  identifiers.
- Grafana assets no longer advertise template variables that their queries do
  not enforce (SR-10). The shipped dashboards are explicitly fixed-window,
  whole-dataset aggregate views. Tenant and team authorization must be applied
  through server-side query policy and data-source or folder permissions.

## Verification

The release includes finding-specific regression tests plus the supported
offline suite entry points:

```bash
python tests/test_berserk_mcp.py
python -W error -m unittest discover -s tests
```

Dashboard JSON validation, bytecode compilation, source-distribution and wheel
builds, and an isolated wheel smoke test are also part of the release gate.
