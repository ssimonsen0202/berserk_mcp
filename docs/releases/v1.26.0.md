# v1.26.0 — Untrusted-data fencing, tool tiers, and just-in-time discovery

Released: 2026-08-24

The largest release since v1.24.0's MCP protocol adaptation: three real
tool-layer capability additions, one new tool, a source-of-truth security
fix, and a tooling-schema-size lever validated with real model-eval data
rather than asserted.

## Features

- **Untrusted-data fencing** (issue #11). Log and trace body content
  returned by any tool is now explicitly fenced as untrusted,
  attacker-influenceable data rather than left to blend in with trusted
  output — a real prompt-injection-shaped gap for a tool whose whole job is
  surfacing arbitrary ingested telemetry to a model.
- **Wrong-answer containment** (issue #12), documented and tested: the
  specific failure modes this design is meant to prevent (a model
  confidently answering from stale or wrong data) are now named, tested
  against, and CI-gated (issue #13) rather than implicit.
- **Tool tiers** (issue #4), orthogonal to role lanes — tools can be grouped
  into a reduced-schema tier independent of which role lane exposes them,
  the mechanism `find_tool` discovery mode (below) builds on.
- **Just-in-time tool discovery via `find_tool`** (issue #14, opt-in via
  `BERSERK_MCP_DISCOVERY=1`). Instead of listing the full tool catalog
  up front, discovery mode exposes 8 fixed anchor tools plus `find_tool` as
  a search-by-intent entry point that returns matching candidates with
  their full `inputSchema` inline. Measured against a real MCP handshake:
  the full 70-tool schema costs ~17,560 tokens; discovery mode costs
  ~1,386 — a 92% reduction. A recall-gate test
  (`tests/test_tool_discovery.py`) requires every shipped tool to be
  reachable by at least one realistic phrasing before it ships; current
  measured recall is 100% across 210 phrasings.
- **`agent` parameter on the base Claude Code query tools** (issue #42).
  `claude_recent`/`claude_sessions`/`claude_tools`/`claude_errors`/`claude_search`
  take an optional `agent` parameter, default `claude-code`, letting you
  query a different ingested agent's data with the same tool — fully
  backward compatible, zero behavior change when omitted.
- **`claude_quota_status`** (issue #43): a live Claude Code quota-window
  check. Tries a real-time read from Anthropic's account-usage endpoint
  first (macOS only, reads Claude Code's own Keychain credential — an
  undocumented endpoint, so treat exact fields as best-effort), falling
  back to a log-derived token estimate over the trailing window when the
  live path is unavailable for any reason. Never requires the ingestion
  daemon running.

## Fixes

- **`_schema_fetcher` no longer swallows backend errors** (issue #32). It
  discarded the error flag on all four of its `run_bzrk` calls, so a
  genuine backend failure (auth error, timeout, connection refused) never
  raised — `schema_registry.get_schema_snapshot()`'s failure-handling
  never triggered, and the error text got normalized and cached as if it
  were real schema output, with `source_status` marked `"fresh"`. Now
  raises when any of the four calls fail, correctly falling back to a
  stale cache or reporting `"unavailable"`.
- `bzrk search` calls now force `--no-stream` consistently.
- `save_query`'s `roles` property was missing a required JSON Schema field.

## Model-choice guidance corrected

Real eval data (8 models: 2 local via Ollama, 6 cloud via OpenRouter; full
methodology in
[docs/model-routing-cost-validation-2026-08-23.md](../model-routing-cost-validation-2026-08-23.md))
found the previous "7B is the sweet spot" local-model guidance in this
README was wrong: 7-8B models scored 5-7% tool-selection accuracy against
the full schema, below a dumb keyword-matching baseline. The measured
reliability floor is the ~24B parameter class. See "Choosing a model"
below for the corrected guidance.

## Verification

- Full unit suite: 863 tests passing, 1 skip.
- `evals/mcp_protocol_smoke.py --include-http`: all pass.
- `find_tool` recall gate: 100% across 210 phrasings covering all 70
  shipped tools.
- A real `_schema_fetcher` failure was reproduced end-to-end
  (`source_status` confirmed `"unavailable"`, not `"fresh"`).
