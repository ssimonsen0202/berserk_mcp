# v1.37.11 — record the real model id for generated queries

Released: 2026-11-17

## What changed

- **The bug.** The author ladder stored `generated_by.model` from the
  `BERSERK_LLM_<PROVIDER>_MODEL` variable and fell back to the provider name.
  With no variable set, provenance read "hermes" or "anthropic" instead of a
  model id. Hermes also discovers its model from the endpoint, so the variable
  was usually unset.
- **The fix.** A new `_provider_model(provider)` returns the model id for a
  provider. Anthropic and OpenAI use their variable or a module default
  (`_DEFAULT_ANTHROPIC_MODEL`, `_DEFAULT_OPENAI_MODEL`). Hermes uses its
  configured or discovered id.
- **One lookup per attempt.** The ladder resolves the model once before each
  call, sends it with `llm_complete(..., model=...)`, and records that same
  value. It does not look the model up again after the call. A later lookup
  could cost a network request and could name a different model.
- **Discovery errors.** A Hermes discovery error counts as a provider failure,
  like any other error on the first attempt.
- **Compatible.** `llm_complete` takes an optional `model` argument. When it
  is missing, `llm_complete` resolves the model itself. Existing callers work
  unchanged. The string "unknown" is never written to provenance.
- **`review_generated`.** It already prints `generated_by.model`. It now shows
  the real id.

## Verification

`tests/test_parser_factory.py` adds five tests. Each failed before the change.
Three existing test doubles for `llm_complete` now accept `model=None`.
