# v1.24.0 — MCP 2026 adaptation and safe HTTP transport

Released: 2026-07-31

v1.24.0 keeps the stable `2025-06-18` stdio contract as the default and adds
the first gated `2026-07-28` compatibility path. Existing Claude Desktop and
Claude Code stdio deployments should not see response-shape changes unless
operators explicitly enable the new mode.

## Highlights

- Added explicit dual-era MCP protocol scaffolding:
  `2025-06-18` remains the default, while `2026-07-28` is gated behind
  `BERSERK_MCP_ENABLE_2026_07_28=1`.
- Added gated `server/discover` support for modern clients, including server
  metadata, capability reporting, and role-scoped tool discovery.
- Added modern `tools/call` result envelopes with `resultType` while preserving
  legacy `content` and `isError` behavior.
- Added structured reporting output for AI FinOps and management-facing tools,
  including modern `outputSchema` metadata and `structuredContent` extraction
  from JSON report envelopes.
- Added private tool-list cache hints for modern clients. Cache metadata is
  intentionally private and short-lived so role-scoped tool visibility is not
  shared across users or roles.
- Added modern `input_required` guidance for broad or expensive custom search
  requests and for FinOps attribution gaps, allowing an agent to ask the user
  for narrowing information before spending cluster or token budget.
- Added an in-memory task lifecycle for eligible long-running tools:
  task creation through `as_task`, `tasks/get`, `tasks/cancel`, role isolation,
  expiry, and redacted result storage.
- Added an optional stdlib HTTP transport with safe defaults:
  disabled by default, loopback bind by default, remote bind fail-closed unless
  auth, Host allowlisting, and CIDR allowlisting are configured, request-size
  limits, concurrency limits, no CORS preflight support, and a minimal
  `/healthz` endpoint.
- Added deployment guidance for putting the HTTP listener behind an HTTPS/TLS
  reverse proxy, including Caddy, nginx, Host validation, CIDR allowlisting,
  and optional proxy mTLS guidance.
- Added `.env.example` with commented-out, secure-by-default HTTP and MCP 2026
  settings so operators can start from a safe template.

## Compatibility

- Default behavior remains stdio plus MCP `2025-06-18`.
- Modern `2026-07-28` features require both the environment feature flag and
  request metadata for the modern protocol path.
- Legacy `tools/list` and `tools/call` response shapes remain unchanged.
- HTTP transport is opt-in. Without `BERSERK_MCP_HTTP_ENABLE=1`, no network
  listener is opened.

## Verification

Coverage added in this release includes regression tests for:

- legacy protocol-shape stability;
- gated modern protocol selection;
- `server/discover`;
- modern `tools/call` result envelopes;
- structured reporting output;
- tool-list cache hints;
- `input_required` guidance;
- task lifecycle creation, retrieval, cancellation, expiry, redaction, and role
  isolation;
- HTTP safe defaults, remote bind validation, Host and CIDR allowlisting,
  bearer auth, request-size limits, concurrency limits, CORS rejection, and
  trusted-proxy forwarded IP handling;
- documentation/config coverage for the HTTP and MCP 2026 operator-facing
  settings.
