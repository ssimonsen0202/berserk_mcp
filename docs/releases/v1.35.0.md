# v1.35.0 — Output redaction closes the non-JSON gaps

Released: 2026-09-26

Security item 2d. The output redactor found credential keys in any text, but
outside JSON it often removed only the first word of the value. The rest of
the secret reached the model. `redact` is the default output mode, so this
was a leak, not only a reporting gap.

## What changed

After a credential key, the whole value is now removed:

| Value form | Before | Now |
|---|---|---|
| YAML block scalar (`password: \|` then indented lines) | the lines leaked | removed |
| Key alone on its line, value indented below | the next line's first word was removed | the indented lines are removed |
| Quoted value with a literal line break | the text after the break leaked | removed to the closing quote |
| Unterminated quoted value | removed to the end of the line; later lines leaked | removed to the end of the text |
| Bare value with spaces (`password = correct horse`) | only the first word was removed | removed to the end of the line, stopping before a following `key=` logfmt field |
| Typographic or backtick quotes (`“…”`, `‘…’`, `«…»`, `` `…` ``) | only the first word was removed | removed to the closing quote |

More keys and forms are recognised:

- **Prefixed keys:** `db_password`, `client_secret`, `refresh_token`,
  `X-Api-Key`, `AWS_SECRET_ACCESS_KEY`, `spring.datasource.password`. The key
  must end the name, so `max_tokens`, `tokens` and `password_policy` still do
  not match.
- **New key names:** `passphrase`, `credential(s)`, and `access_key`,
  `secret_key`, `private_key`, `signing_key`, `encryption_key`, `client_key`.
- **`Authorization` headers** with the Basic, Digest, NTLM or Negotiate scheme
  (and `Proxy-Authorization`). `authorization: denied` is left alone.
- A bare `true`, `false`, `null`, `none`, `nil`, `~`, `yes` or `no` after a key
  is a setting, not a secret, and is left alone (`persist-credentials: false`).

## Behaviour changes

- **Multi-line values fail closed past 64 KB.** A value that spans lines
  (quoted, unterminated or a block scalar) is removed in full up to 64 KB.
  Past that, the whole result becomes `[REDACTED:redaction_limit]` with the
  new reason `multiline_value_too_large`, as the other redaction limits do,
  rather than return a partial redaction. A quoted value on one line has no
  limit.
- **An unterminated quote takes the rest of the text.** One truncated
  `password="…` in a result now removes everything after it (or fails the
  result closed if more than 64 KB follows). This was "to the end of the
  line" before, which leaked any later lines of the value.
- A bare value after a bare key now runs to the end of the line. A second
  secret on the same line is still removed, but inside the same placeholder,
  so the findings count it once.
- After a quoted key (`"password": …`), a bare value ends at `,`, `}`, `]` or
  the line end, as in JSON.

## Review

Two Codex review passes. The first found a cache-boundary case that left the
next value in clear, partial redaction past the size limits, and two false
positives (`GET /password=public`, `password: false # comment`). All are
fixed and have regression tests. The second pass found nothing further.

`_credential_matches`, `_quoted_value_end` and `_block_end` are registered in
`tests/security_reviews.json`.

## False-positive check

Before release, the old and new redactors were run over local text; only
counts, types and key names were printed:

- **System and application logs** (55 files, 53 MB): no change except two
  prose matches (`(credential: include)` in an Electron error).
- **Claude Code transcripts** (47 files, 36 MB): the new rules removed 0.06%
  of the characters, against 0.002% before. Most new matches are real
  credential keys, such as `OPENROUTER_API_KEY`, `ANTHROPIC_AUTH_TOKEN`,
  `AWS_SECRET_ACCESS_KEY` and `POSTGRES_PASSWORD`.

The same comparison against the live Berserk store is pending: the `bzrk`
CLI session had expired.

## Performance

Keys inside a matched value are skipped, except keys on the later lines of a
multi-line quoted value: a quote there may open another key's value rather
than close this one, so those keys are scanned too and overlapping spans are
merged. Rescans are confined to the last 64 KB of a text (further out, the
input fails closed first). Adversarial 1 MB inputs finish in under 0.5 s; a
timing test covers each shape.

## Limits

The redactor is key-anchored. A secret in free prose with no key, split
across log records, or encoded is not caught. Scrub secrets at ingest.
